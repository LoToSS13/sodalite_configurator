# Правила проекта

- Не выполнять никаких операций с GitLab. Все изменения — только локально; Figma используется для чтения, пока пользователь явно не изменит это ограничение.
- Не запускать `flutter analyze` и `dart analyze`.
- Не писать и не запускать тесты без явного запроса пользователя.
- Ревью интерфейса сейчас проводить на desktop. Мобильные экраны не входят в текущий объём.

## Компоненты интерфейса

1. Перед реализацией проверить Sodalite 2.0 в Figma: файл `JsnlUudhlN3ZuGGWYcHKU8`, страница компонентов `89:15459`. Читать не только картинку, но и описание, варианты, размеры, отступы, состояния, поведение и анимацию. Использовать variables и текстовые стили.
2. Если подходящего компонента нет, **до создания нового компонента обязательно обратиться к Mobbin MCP**. Посмотреть изображения подходящих desktop-примеров, сравнить их с задачей конфигуратора и выбрать наиболее подходящий. Зафиксировать ссылку Mobbin и причину выбора. Mobbin определяет паттерн, визуальный язык остаётся Sodalite.
3. Создать отсутствующий компонент локально со спецификацией состояний и поведения, затем согласованную реализацию. Не выдавать адаптацию или собственный компонент за точную копию из Figma. Для составного блока сначала переиспользовать имеющиеся примитивы. Реестр и спецификации находятся в `docs/component-audit.md`.
4. Если Figma или Mobbin недоступны, прямо сообщить об этом и не представлять непроверенный вариант как сверенный с источником.
5. При расхождении описания Figma с нарисованным вариантом зафиксировать оба значения и основание выбранного решения в отчёте.
6. Проверять desktop-сборку и визуальное поведение. Не заменять визуальную проверку утверждением, что код компилируется. Ограничения проверки указывать явно.
7. После ревью давать таблицу: компонент → источник → расхождение → исправление → результат проверки.

Согласованные расширения палитры: `accentStrong #0065DC`, `errorText #B42318` — для контрастного текста. По последнему указанию пользователя синий у кнопок (заливка Primary, текст Ghost и добавление блока) — исходный `accent #0075FF` из Figma; не заменять его на `accentStrong`.

Наведение: увеличение до 102% без изменения фона **только у кнопок и кликабельных карточек черновиков**. Кнопки-иконки и добавление блока тоже входят в это правило. Контейнеры формы («Адрес модуля», «Карточка модуля», вложенные блоки), информационные и пустые карточки, поля, навигацию, строки меню/замечаний, переключатели и палитру не масштабировать. Применять через общий `SodalitePress`. Не складывать hover-масштаб вложенных элементов; layout и область нажатия остаются стабильными. Disabled/loading не реагируют на hover. Состояния выбора, клавиатурного фокуса и нажатия независимы от hover.

Исключение: блок «С чего начнём?» на главной странице не масштабируется при наведении. Его кнопки сохраняют hover102%.

Валидация формы: при открытии редактора нетронутые поля и карточки не показывают ошибки. Ошибку поля показывать после ухода фокуса из него; после этого обновлять при вводе. Полную проверку раскрывать по «Проверить» или попытке скачать ZIP. Счётчики в навигации и карточках учитывают только раскрытые ошибки. Реальная валидация и запрет экспорта некорректной конфигурации действуют всегда; состояние показа ошибок не сохранять в черновик.

Фокус общих текстовых кнопок `SodaliteButton` обозначать контуром1.5, без фоновой заливки; hover102% и pressed остаются независимыми. Идентификатор модуля показывается как выбираемый текст с отдельным действием «Изменить», без имитации редактируемого поля. Ввод нового значения — в диалоге с явным сохранением.

У строк переключателей не подсвечивать весь фон при нажатии или фокусе. Вся строка остаётся кликабельной; фокус обозначается контуром самого переключателя, изменение значения — его обычной анимацией.
